# W800 AT 指令说明（给 Codex 使用）

> 来源：`WM_W800_SDK_AT 指令用户手册 V1.1`
> 目标：为 Codex 提供一份**可编码**的 W800 AT 指令摘要，便于实现 MCU 侧 `w800_at / w800_wifi / w800_socket / cloud_http_client` 模块。:contentReference[oaicite:1]{index=1}

---

## 1. 模块概述

W800 使用一套基于 ASCII 的 `AT+` 命令协议，通过 UART 与外部 MCU 通信。AT 命令主要覆盖：

- 系统控制
- Wi-Fi 参数设置
- 网络控制
- Socket 通信
- HTTP Client
- 蓝牙（本项目当前可忽略）

手册明确说明：W800 的 AT 协议采用“命令 + 响应”模式，绝大多数命令都需要等待前一条命令处理完成后再发下一条；如果前一条命令尚未处理完成，新的命令会被丢弃且**不返回任何消息**。:contentReference[oaicite:2]{index=2}

## 2. AT 协议基础

### 2.1 命令格式

```text
AT+<CMD>[op][para1],[para2],...[paraN]<CR>
说明：
• AT+：命令前缀
• CMD：指令名
• op：操作符，可为：
• =：设置参数 / 返回值前导符
• =!：设置并同步到 Flash
• =?：查询当前设置
• <CR>：回车，ASCII 0x0d
响应格式：
Plain text
复制
￼
+<RSP>[op][para1],[para2],...[paraN]<CR><LF><CR><LF>
其中：
• RSP=OK 表示成功
• RSP=ERR 表示失败
手册还说明：
• AT 指令命令字和多数参数不区分大小写
• 但参数 SSID 和 Key 的取值区分大小写
• 参数之间用 , 分隔
• 为避免解析歧义，建议单个字符串参数用双引号包裹
• 查询操作是 AT+XXX=?，不是 AT+XXX?。
WM_W800_SDK_AT指令用户手册
2.2 二进制传输特殊性
AT+SKSND、AT+SKRCV 这类命令在 AT 文本响应之后还会进入二进制收发阶段。实现时必须把：
• AT 文本行解析
• 定长二进制 payload 收发
分成两层状态机，不能只按 \r\n 文本行处理。

8. Socket 通信（重点）
8.1 建立 socket：AT+SKCT
Plain text
复制
￼
AT+SKCT=[protocol],[cs],[host_timeout],<remote_port>,<local_port>
+OK=<socket>
参数：
• protocol
• 0：TCP
• 1：UDP
• cs
• 0：Client
• 1：Server
• host_timeout
• client 模式下：目标主机，可填 IP 或域名
• server+TCP 模式下：连接超时秒数
• remote_port：远端端口
• local_port：本地端口
• 返回值 socket：socket 号
手册示例（TCP client）：
Plain text
复制
￼
AT+SKCT=0,0,"192.168.1.100",1000,1000
+OK=1
注意：
• Host 参数建议加双引号
• 代码中可优先使用 IP，后续再扩展域名
• +ERR=-4 通常表示参数格式不符合要求。
WM_W800_SDK_AT指令用户手册
8.2 发送数据：AT+SKSND
Plain text
复制
￼
AT+SKSND=<socket>,<size>
+OK=<actualsize>

[data stream]
关键行为：
• 先发 AT+SKSND
• 收到 +OK=<actualsize> 之后
• 再发送 原始二进制数据
• 模块在收满指定长度后自动结束发送阶段
• 若 1 秒内未收满，也会结束发送并把已收数据发出去
• 多余数据会被丢弃
重点：不是等待 > prompt。
MCU 代码必须按“收到 +OK=size 后再直接推二进制”的方式实现。
WM_W800_SDK_AT指令用户手册
8.3 接收数据：AT+SKRCV
Plain text
复制
￼
AT+SKRCV=<socket>,<maxsize>
+OK=<size>

[data stream]
行为：
• 先返回 +OK=<size>
• 然后输出 size 字节原始二进制数据
因此接收层必须支持“文本头 + 定长二进制数据”混合解析。
WM_W800_SDK_AT指令用户手册
8.4 查询 socket 状态：AT+SKSTT
Plain text
复制
￼
AT+SKSTT=<socket>
+OK=<socket>,<status>,[host],[HostPort],[LocalPort],[rx_data]
状态值：
• 0：断开
• 1：监听
• 2：连接
其中 rx_data 表示接收缓冲区中的数据长度。
MVP 建议采用：
• SKCT 建连
• SKSND 发送
• 轮询 SKSTT
• rx_data > 0 时 SKRCV 拉取响应
而不是一开始就依赖主动上报。

10. HTTP Client 指令 AT+HTTPC
W800 手册还提供了 AT+HTTPC：
Plain text
复制
￼
AT+HTTPC=<url>,<verb>,<user=postdata>
+OK=<sessionid>
参数：
• url：远程 HTTP 地址
• verb
• 0：GET
• 2：POST
• 3：PUT
• postdata：POST/PUT 时上传的数据
但注意：
• 使用 AT+HTTPC 前需要先打开 AT+SKRPTM=1
• 成功时会主动上报：
• +HTTPCRPT=sessionid,totallen
• 失败时会主动上报：
• +HTTPCERRRPT=sessionid,error
手册还列出了 HTTPC 错误码，如不能解析主机名、socket 连接失败、socket 超时、http 头错误等。

对本项目的建议
对于当前 MCU + W800 + 云端 ASR MVP，优先推荐：
• 不直接用 AT+HTTPC
• 先使用 Socket + 手工拼 HTTP 报文
• 原因：
• 更容易控制二进制 WAV body
• 更容易调试
• 更适合 Codex 实现最小可用网络层
