# 数字语音模型上板说明（RA6M5 + Keil）

## 1. 语言与工程要求（必须）
- `digit_model_int8.tflite` 使用 TensorFlow Lite Micro（TFLM）推理。
- TFLM 接口为 C++，Keil 工程必须启用 C++ 编译单元。
- 推荐方式：业务逻辑保持 C；推理模块用 C++；通过 `extern "C"` 暴露 C 接口给 C 文件调用。

## 2. 固定上板文件
- `digit_model.c`
- `digit_model.h`

文件作用：
- `digit_model.c`：模型二进制数组 `g_digit_model_data[]`
- `digit_model.h`：模型数组与长度声明
- 当前模型长度：`g_digit_model_data_len = 370528` 字节

## 3. 当前模型固定参数（必须一致）
模型文件：`digit_model_int8.tflite`

输入张量：
- shape：`[1, 40, 150, 1]`（NHWC）
- dtype：`int8`
- quantization：`scale = 0.03763900697231293`, `zero_point = -33`

输出张量：
- shape：`[1, 10]`
- dtype：`int8`
- quantization：`scale = 0.00390625`, `zero_point = -128`

类别映射：
- 输出下标 `0~9` 对应数字 `0~9`

算子（MicroMutableOpResolver 必须注册）：
- `ADD`
- `CONV_2D`
- `MAX_POOL_2D`
- `MUL`
- `RESHAPE`
- `FULLY_CONNECTED`
- `SOFTMAX`

## 4. 与 PC 完全一致的预处理流程（板端必须复现）

### 4.1 音频输入约束
- 采样率：`16000 Hz`
- 单声道
- 每个数字目标时长：`1.5 s`
- 目标采样点数：`24000`

如果板端采样率不是 16k，则需先重采样到 16k 后再进入后续流程。

### 4.2 `trim_and_fit`（有效语音截取 + 定长）
参数：`top_db = 30`

步骤：
1. 计算峰值 `peak = max(abs(audio))`
2. 阈值 `threshold = peak * 10^(-top_db/20)`
3. 找到 `abs(audio) >= threshold` 的首尾活动区间
4. 在活动区间前后各扩展 `0.03 s`（480 点）
5. 若长度大于 24000：中心裁剪到 24000
6. 若长度小于 24000：左右补零到 24000

### 4.3 幅度归一化
- `audio = audio / max(abs(audio))`（峰值归一化）
- 峰值极小时（接近 0）保持原值

### 4.4 预加重（Pre-emphasis）
参数：`coef = 0.97`

公式：
- `y[0] = x[0]`
- `y[n] = x[n] - 0.97 * x[n-1]`

### 4.5 STFT 与 Log-Mel 特征
固定参数：
- `n_fft = 1024`
- `win_length = 400`
- `hop_length = 160`
- `noverlap = 240`
- `window = hann`
- `boundary = None`
- `padded = False`
- `n_mels = 40`
- `fmin = 20 Hz`
- `fmax = 7600 Hz`
- `TARGET_FRAMES = 150`

步骤：
1. STFT 得到复频谱 `stft`
2. 功率谱 `power = |stft|^2`
3. 乘 Mel 滤波器组得到 `mel`
4. `log_mel = log10(max(mel, 1e-10))`
5. 时间帧定长到 150：超出截断，不足补零
6. 单样本标准化：`(log_mel - mean) / (std + 1e-6)`
7. 增加通道维度，得到 `[40, 150, 1]`

## 5. PC 训练流程（`train_model.py`）

### 5.1 数据读取与划分
- 从 `data/0` 到 `data/9` 读取全部 `.wav`
- 按类别分层划分训练/测试：`80% / 20%`
- 每个类别测试集至少保留 1 条样本

### 5.2 数据增强（仅训练集）
- 每个原始训练样本额外生成 `5` 个增强样本（`AUGMENT_PER_SAMPLE=5`）
- 采用分层增强策略（音量/噪声/时间拉伸/音高/共振峰/混响/SpecAugment）
- 测试集不做增强

### 5.3 网络结构（量化前）
- `Conv2D(12, 3x3, same, relu)`
- `BatchNormalization`
- `MaxPool2D(2x2)`
- `Dropout(0.15)`
- `Conv2D(16, 3x3, same, relu)`
- `BatchNormalization`
- `MaxPool2D(2x2)`
- `Dropout(0.15)`
- `Conv2D(24, 3x3, same, relu)`
- `BatchNormalization`
- `Flatten`
- `Dense(40, relu)`
- `Dropout(0.25)`
- `Dense(10, softmax)`

### 5.4 训练参数
- `RANDOM_SEED = 44`
- `EPOCHS = 80`
- `BATCH_SIZE = 16`
- `LEARNING_RATE = 1e-3`
- EarlyStopping：`monitor=loss`, `patience=8`, `min_delta=1e-4`
- ReduceLROnPlateau：`monitor=loss`, `factor=0.3`, `patience=3`, `min_lr=1e-6`

### 5.5 量化导出
- 使用代表性数据集导出全整型 `INT8` TFLite
- 输入/输出均为 `int8`

## 6. PC 测试流程（`test_model.py`）

### 6.1 单数字识别
1. 录音（默认 `1.5s`）
2. 调用 `extract_feature_from_audio`（即第 4 节完整流程）
3. 输入量化：`q = round(x / 0.03763900697231293 + (-33))`
4. 裁剪到 `[-128, 127]`
5. TFLite 推理
6. 输出解量化：`y = (q - (-128)) * 0.00390625`
7. 取 `argmax` 作为识别数字

### 6.2 连续四位识别
默认录音时长：`3.6s`

分段流程（当前实现为单一 VAD 候选）：
1. 先做 `audio = normalize_audio(audio - mean(audio))`
2. 帧参数：`frame_len=400`, `hop=160`
3. 计算每帧 RMS
4. 遍历阈值比例 `ratio in [0.15, 0.12, 0.10, 0.08]`
5. 阈值：`threshold = max(max_rms * ratio, median_rms * 0.5)`
6. 二值掩码后做形态学：膨胀 3 次、腐蚀 2 次
7. 段过滤：保留时长 `>=0.3s`
8. 段合并：相邻间隔 `<0.15s` 则合并
9. 候选评分：段数接近 4 + 平均时长接近 `0.6~1.2s`
10. 若无有效候选，回退到等分 4 段
11. 规范到 4 段：多则合并、少则切分最长段
12. 时长约束：
- `<0.6s` 扩展到 `0.6s`
- `>1.2s` 中心截成 `1.0s`
13. 修正重叠（重叠区中点切分）
14. 每段单独：归一化后定长到 `1.5s`（不足补零，超长中心裁剪）
15. 对每段执行第 4 节的 `audio_to_feature` 提取特征并推理
16. 拼接成 4 位数字结果输出

## 7. RA6M5 上板实现建议（面向初赛）
- 音频采集建议使用 `r_ssi`（I2S）+ `r_dmac`（DMA）双缓冲，稳定拿到 16k 单声道流。
- 预处理建议在 M33 侧用 CMSIS-DSP 实现（预加重、窗函数、FFT、功率谱）。
- Mel 滤波器系数建议离线生成并固化到 Flash，确保与 PC 一致。
- 板端必须严格复现第 4 节参数；只要参数有偏差，识别率会明显下降。
- 初赛阶段可先保证“单数字识别完全一致”，再接“连续四位分段识别”。

## 8. Keil 固定接入步骤
1. 将 `digit_model.c`、`digit_model.h` 加入工程
2. 在 C++ 推理模块加载模型：`tflite::GetModel(g_digit_model_data)`
3. 按第 3 节注册算子并创建 `MicroInterpreter`
4. 分配 `tensor_arena` 并执行 `AllocateTensors()`
5. 按第 4/6 节流程送入特征并推理

## 9. 一致性要求（最重要）
- 板端与 PC 端必须在以下项完全一致：采样率、时长、`top_db`、预加重、STFT 参数、Mel 参数、时间帧数、标准化、输入输出量化参数。
- 不允许随意更改任一参数；如果要改，必须在 PC 重新训练并同步更新模型和文档。
